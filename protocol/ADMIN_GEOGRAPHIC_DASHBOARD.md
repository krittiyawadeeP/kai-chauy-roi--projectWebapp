# การบริหารนโยบายกลางและแดชบอร์ดรายพื้นที่

## การใช้งาน

เลือกบทบาทภาครัฐและเข้าสู่ระบบด้วยบัญชี `ADMIN` เมนูฝั่งซ้ายเปิดหน้าภาพรวมรายพื้นที่ นโยบายอัตราร่วมจ่าย ภารกิจ การวิเคราะห์ และทะเบียนร้านค้า

หน้าเดียวเจาะลึกตามลำดับ ประเทศ → ภาค → จังหวัด → อำเภอ/เขต → หมุดร้านค้า เลือกจังหวัดจากตัวกรอง แผนที่ หรือตารางเพื่อเปลี่ยนแผนที่เป็นขอบเขตอำเภอ/เขต และเปลี่ยนตารางเป็นรายอำเภอ ตัวกรองและเส้นทางพื้นที่ด้านบนย้อนกลับไปดูทั้งจังหวัด/ภาค/ประเทศได้ เมื่อเปลี่ยนพื้นที่แม่จะล้างอำเภอที่เลือกไว้

หมุดร้านค้า ปุ่มดูที่ตั้งร้าน และการขยายมุมมองตามพิกัดร้านจะแสดงเมื่อเลือกอำเภอ/เขตแล้วเท่านั้น โดยแสดงเฉพาะร้านในอำเภอ/เขตนั้น เมื่อย้อนกลับหรือเปลี่ยนจังหวัด/ภาคจะซ่อนหมุด ส่วนจำนวนร้านในสรุปและรายงานยังแสดงทุกระดับพื้นที่ตามเดิม

ช่องอำเภอเปิดเมื่อเลือกจังหวัดและโหลดรายการอำเภอสำเร็จ หาก backend รุ่นเก่าไม่ส่ง `districts` หน้าจอจะแจ้งให้รีสตาร์ต backend แทนการแสดงรายการว่าง `npm run dev` ฝั่ง backend ใช้ `tsx watch` เพื่อโหลดโค้ดใหม่อัตโนมัติ การรีสตาร์ตจะทำให้ token เดิมหมดอายุเพราะเซสชันเก็บในหน่วยความจำ ต้องรีเฟรชหน้าและเข้าสู่ระบบ Admin ใหม่

ตัวชี้วัดสีแผนที่มีเงินหมุนเวียน เงินรัฐสมทบ เงินประชาชนจ่าย และจำนวนร้านค้า ไม่มีตัวเลือกจำนวนธุรกรรมแล้ว แต่ยังแสดงจำนวนธุรกรรมในสรุปและรายงานตามเดิม ตารางเรียงตามเงินหมุนเวียนหรือจำนวนร้านได้ CSV ใช้พื้นที่และการเรียงเดียวกับตาราง พร้อมระบุชื่อจังหวัด อำเภอ/เขต ภาค ขอบเขตข้อมูล และเวลาของข้อมูลที่ดึงจาก API

## แหล่งข้อมูลและความหมาย

- `GET /api/admin/dashboard/geography` ต้องมี Bearer token ของ ADMIN
- ยอดเงินหมุนเวียนรวมและยอดร่วมจ่ายรวมจาก `sales_transactions` เฉพาะ `Status = COMPLETED` เป็นยอดสะสมตั้งแต่เริ่มโครงการ ไม่มีการคำนวณยอดย้อนหลังใหม่ตามอัตราปัจจุบัน
- พื้นที่ของธุรกรรมอ้างอิง `District_ID -> districts.Prov_ID` จำนวนร้านค้าเป็นจำนวนร้านค้าที่มีทะเบียนในจังหวัด ไม่ใช่จำนวนร้านที่มีรายการขาย
- API เดิมเพิ่ม `districts` เป็นสรุปยอดซื้อขายและร้านค้ารายอำเภอ/เขต โดยเทียบชื่อไทย/อังกฤษภายในจังหวัดกับ `shared/districts.ts` ก่อนจับคู่ขอบเขตแผนที่ ไม่ใช้ Dist_ID ในฐานข้อมูลเป็นรหัสแผนที่โดยตรง ชื่อที่จับคู่ไม่ได้ใช้ code `db-<Dist_ID>` และยังเก็บยอดไว้ในรายงาน พร้อมแจ้งว่าแผนที่จับคู่ไม่ได้
- API เดิมส่ง `merchants` เพิ่มเติม ได้แก่ชื่อ ประเภท พิกัด และพื้นที่ของร้าน โดยไม่ส่งข้อมูลบัญชีเจ้าของร้าน หมุดสีส้มแสดงที่ตั้งจริงจาก `merchants.Lat/Lng` และกรองตามภาค/จังหวัด/อำเภอเดียวกับรายงาน `districtCode` จับคู่ด้วยชื่อและจังหวัดเหมือนสรุปอำเภอ คลิกหมุดหรือกด Enter เมื่อโฟกัสหมุดเพื่อดูรายละเอียด
- พิกัดต้องไม่เป็น null เป็นจำนวนจำกัด และอยู่ในช่วง WGS84 (ละติจูด -90 ถึง 90 ลองจิจูด -180 ถึง 180) ร้านที่ไม่มีพิกัดถูกต้องยังนับในจำนวนร้านทั้งหมด พร้อมแสดงจำนวนที่ไม่สามารถปักหมุดได้ ไม่มีการใช้พิกัดสมมติแทนข้อมูลที่ขาด
- ฝั่งร้านค้าเก็บพิกัดที่ยังไม่มีเป็น null และแสดงว่า “ยังไม่ระบุ” ตัวเลือกแผนที่เปิดภาพรวมประเทศโดยไม่ปักหมุดจนกว่าจะเลือกจุด กรอกพิกัดครบ หรืออ่าน GPS สำเร็จ หาก GPS ล้มเหลวจะแจ้งข้อผิดพลาดโดยคงพิกัดเดิม ไม่มีปุ่มพิกัดตัวอย่างและไม่มีการใช้พิกัดนนทบุรีแทน ข้อมูลที่เคยบันทึกผิดต้องแก้ด้วยตำแหน่งจริงของร้าน ไม่ย้ายหมุดไปศูนย์กลางจังหวัดอัตโนมัติ
- มุมมองแผนที่ครอบคลุมทั้งขอบเขตพื้นที่และพิกัดร้านที่ผ่านตัวกรอง จึงไม่ซ่อนร้านที่พิกัดจริงอยู่นอกกรอบพื้นที่ทะเบียน พร้อมข้อความให้ตรวจสอบและปุ่ม “ดูที่ตั้งร้าน” เพื่อซูมไปที่หมุดโดยตรง การตรวจนอกกรอบนี้ใช้กรอบสี่เหลี่ยมของขอบเขต ไม่ใช่การรับรองว่าพิกัดอยู่ในเขตการปกครองจริง
- พื้นที่ตัวชี้วัดเป็นศูนย์ใช้สีทรายและเส้นขอบเข้ม แยกจากพื้นหลังสีฟ้าอ่อน พร้อมคำอธิบายสีและจำนวนร้านทั้งหมด/ร้านที่ปักหมุดได้จากฐานข้อมูลใต้แผนที่
- วงเงินจัดสรร/คงเหลืออ้างอิงจังหวัดที่อยู่ของผู้รับ (`users.Province_ID`) จึงอาจต่างพื้นที่จากที่ซื้อสินค้า
- ไม่มีข้อมูลอำเภอของผู้รับสิทธิ์ในฐานข้อมูล จึงไม่กระจายวงเงินสิทธิ์ลงอำเภอ เมื่อเลือกอำเภอจะซ่อนวงเงินจังหวัดและแจ้งข้อจำกัดนี้ ส่วนเงินรัฐสมทบจากธุรกรรมยังแสดงตามอำเภอที่ซื้อขายจริง
- ไม่ใช้หมายเลขลำดับในฐานข้อมูลแทนรหัสจังหวัดมาตรฐาน แต่เทียบชื่อไทย/อังกฤษกับ `shared/geography.ts` ก่อนเชื่อมกับแผนที่
- ครบ 77 จังหวัดในแผนที่ จังหวัดที่ไม่มีข้อมูลจะแสดงศูนย์ ส่วนชื่อจังหวัดที่เทียบไม่ได้หรือผู้รับที่ไม่มีจังหวัดจะแสดงแยกในตารางและรวมในยอดประเทศ
- แผนที่อำเภอ/เขตใช้ reference 928 พื้นที่ รายการที่ไม่มีข้อมูลในฐานข้อมูลยังแสดงศูนย์และระบุว่ายังไม่มีข้อมูล ขอบเขตอำเภอถูกโหลดเมื่อเลือกจังหวัดครั้งแรกและใช้ซ้ำระหว่างเลือกพื้นที่
- แผนที่แสดงขอบเขตแบบย่อเพื่อการรายงาน แบ่ง 6 ภาค (เหนือ 9 กลาง 22 ตะวันออกเฉียงเหนือ 20 ตะวันออก 7 ตะวันตก 5 ใต้ 14)

ขอบเขต `frontend/public/maps/thailand-provinces.geojson`, `thailand-districts.geojson` และรายชื่อพื้นที่ได้จาก [Thailand Canonical Administrative-Names Reference](https://github.com/DevelopedbyWill/thailand-canonical-admin-names) ข้อมูลรายชื่อ CC BY 4.0 และขอบเขต OCHA CODs / mapthai ตามเงื่อนไขต้นทาง ดู attribution ใน `frontend/public/maps/NOTICE.md` และ `SOURCE.md` ข้อมูลแผนที่ถูกเก็บในโปรเจกต์ ไม่เรียก tile server ภายนอกขณะเปิดแดชบอร์ด

## นโยบายร่วมจ่ายส่วนกลาง

- `GET /api/admin/policy` อ่านนโยบายที่มีผลล่าสุด เรียงวันเวลาที่มีผลและ Policy_ID เพื่อให้กรณีบันทึกในวินาทีเดียวกันได้ค่าที่แน่นอน
- `POST /api/admin/policy` รับ `Gov_Pay_Ratio` (อัตรารัฐ 0–1 ไม่รวมปลายช่วง), `Grant_Amount` (วงเงินสิทธิ์ใหม่), `Note` (เหตุผลที่ต้องระบุ) เซิร์ฟเวอร์คำนวณอัตราประชาชนเป็นส่วนที่เหลือ
- นโยบายเดียวใช้กับรายการชำระใหม่ของผู้ใช้ทุกราย/ร้านค้าทุกร้าน ไม่มีฟอร์มปรับอัตราหรือจัดสรรวงเงินรายบุคคลในหน้าตั้งค่านโยบาย
- `/api/merchants/me/sales` อ่านอัตราจากนโยบายกลางทุกคำขอ วงเงินเริ่มต้นของการสมัคร/ออกสิทธิ์ใหม่อ่านจากนโยบายเดียวกัน ยอดสิทธิ์เดิมไม่ถูกรีเซ็ต
- `GET /api/policy` เปิดให้อ่านเฉพาะตัวเลขอัตราและวงเงิน เพื่อให้หน้าประชาชนและร้านค้าแสดงอัตราปัจจุบัน ฝั่ง React รีเฟรชเมื่อเปลี่ยนบทบาท กลับมาโฟกัสหน้าเว็บ ทุก 60 วินาที และหลังบันทึกนโยบายในแท็บเดียวกัน เซิร์ฟเวอร์เป็นผู้ตัดสินยอดเงินจริง
- `GET /api/admin/policy/history` เป็นประวัติวันเวลามีผล ผู้ดำเนินการ และหมายเหตุ
- ค่าเริ่มต้นคงตามโค้ดปัจจุบันของโปรเจกต์: รัฐ 40% / ประชาชน 60% วงเงิน 1,000 บาท ผู้ดูแลปรับได้จากหน้าส่วนกลาง

ต้องมีตาราง `grant_policy` ตาม Prisma schema ที่มีอยู่แล้ว ไม่มีการเพิ่มหรือเปลี่ยนโครงสร้างฐานข้อมูลในงานนี้ ส่วนการวิเคราะห์ ภารกิจ และทะเบียนร้านค้าเดิมยังทำงานผ่าน AppContext เช่นเดิม

## การตรวจสอบ

ข้อมูลร้านจำลองนครปฐม: รัน `npm.cmd run seed:nakhon-pathom` จาก `backend` เพื่อเพิ่มร้าน 10 ร้าน กระจายครบ 7 อำเภอ ชื่อขึ้นต้น `[จำลอง]` และมีบัญชีเจ้าของจำลองแยกร้าน ใช้หมายเลขสังเคราะห์และรหัสผ่านสุ่ม ไม่ได้สร้างธุรกรรม วงเงินสิทธิ์ หรือยอดเงิน พิกัดสุ่มอยู่ภายใน polygon อำเภอจากไฟล์แผนที่ในโปรเจกต์ จึงไม่ใช่ตำแหน่งร้านจริง รันซ้ำจะตรวจและใช้ร้านเดิมโดยไม่เปลี่ยนพิกัดหรือสร้างซ้ำ หากต้องการตรวจเฉพาะการสุ่มพิกัดโดยไม่เชื่อมฐานข้อมูลให้เพิ่ม `-- --check` หลังคำสั่ง

กดรีเฟรชข้อมูลในแดชบอร์ด เลือกจังหวัดนครปฐม แล้วเลือกอำเภอ/เขตเพื่อดูหมุดร้านจำลอง จำนวนร้านต่ออำเภอ: เมืองนครปฐม กำแพงแสน และนครชัยศรี อำเภอละ 2 ร้าน; ดอนตูม บางเลน สามพราน และพุทธมณฑล อำเภอละ 1 ร้าน

โค้ด backend แยกตามเรื่องใน `src/dashboard/`, `src/policy/` และ `src/grants/` โดยเก็บ routes, ฟังก์ชันเฉพาะเรื่อง และ tests ไว้ด้วยกัน `src/routes/admin.routes.ts` เชื่อม routes เหล่านี้หลังตรวจสิทธิ์ Admin ส่วน public policy เชื่อมใน `src/routes/index.ts` ทั้งหมดใช้ URL เดิม

```powershell
npm.cmd run build
npm.cmd run lint --prefix frontend
cd backend
node --import tsx --test src/dashboard/dashboard.test.ts src/policy/policy.test.ts
cd ../frontend
node --import tsx --test src/components/admin/map-bounds.test.ts src/services/adminService.test.ts src/services/merchantService.test.ts
```

ทดสอบการรวมยอด การเชื่อมรหัสจังหวัด การเก็บยอดพื้นที่ไม่ทราบจังหวัด การตรวจนโยบาย การจำกัดสิทธิ์ API และยอดขายหลังปรับอัตรากลางด้วยฐานข้อมูลจำลอง ยังต้องตรวจการทำงานกับ MySQL และภาพหน้าจอในสภาพแวดล้อมใช้งานจริง
